# Проверки версии 0.3.0

Дата: 27 октября 2026 года.

## Выполнено

- Для 0.3.0: 67 локальных тестов, включая реальные TCP-соединения с эмулятором Panasonic NTCONTROL без пароля и с MD5-авторизацией, свежий challenge для каждой команды, три режима и запрос состояния, ошибки авторизации, недопустимые/обрезанные/слишком длинные ответы, потерю подтверждения без повторной отправки, отклонение внедрения команд и ограничение моделей. Полный формат ответа DLVI0 и кодировка двух режимов при задней проекции проверены по подробной спецификации FW300; установка читается по QSP, соблюдается пауза 0,5 секунды между командами, тайм-аут ответа — 10 секунд.
- Прямой тест с настоящим HA 2026.10.2 подтвердил Daylight View среди 15 объектов поддерживаемого Panasonic, вызов select.select_option с чтением результата, недоступность без обращений к Panasonic при охлаждении, сохранение настроек через OptionsFlow с единственной перезагрузкой и выгрузку платформы. У других моделей остаются прежние 14 объектов. Активных платформ теперь шесть (select без объектов для неподдерживаемых моделей).
- Добавлены HA pytest-проверки трёх режимов, диагностики без пароля, восстановления после ошибки независимого соединения, сна/прогрева/охлаждения, однократной отправки при потерянном подтверждении и сохранения прочих объектов при отключении Daylight View. Полный набор выполняется в Linux CI.
- Протокольное основание: команды и ответы Daylight View из спецификации Panasonic FW300NT; NTCONTROL, заголовок 00, TCP 1024 и MD5 username:password:challenge из документации Panasonic по LAN command control. Совместимость на физическом FW300NT ещё не проверена.

- 56 локальных тестов: реальный TCP-эмулятор на `127.0.0.1`, аутентификация PJLink, ошибочные/обрезанные/слишком длинные ответы, тайм-аут после отправки, чтение производителя/модели, состояния прогрева/охлаждения, однократное ИК-включение, параллельные вызовы и отмена. В набор добавлены реальные запросы `LAMP`/`ERST`, корректные и некорректные ответы, нулевой счётчик часов, до восьми ламп, различие предупреждений и ошибок.
- В тот же набор входят проверки мастера настройки и вызовов произвольного `remote`, с подменой только границы Home Assistant: отсутствие передатчика/сервиса/функции обучения, разные поставщики, отсутствие необязательного имени устройства, явный старт и подтверждение обучения, повтор после ошибки.
- Все 56 тестов запускаются отдельно с `probatio` и с прежней `voluptuous` на Python 3.12.14.
- Прямой тест с настоящим Home Assistant **2026.10.2**, Python **3.14.9**, Windows: фактическая загрузка интеграции, создание медиаплеера и диагностического датчика при спящем устройстве, доступность включения через настоящий сервис `media_player.turn_on`, чтение модели в config flow, обучение через сервис произвольного `remote`, переход к подтверждению результата, перенастройка существующей записи и выгрузка сущностей. PJLink и физический передатчик в этом тесте заменены на программные ответы; API, менеджер настроек, платформы и реестры HA настоящие.
- Статическая проверка Python, порядка manifest, структуры переводов EN/RU и соответствия шагов UI.
- Ruff: ошибок нет.
- При упаковке каждый файл архива сравнивается побайтово с исходником, проверяется точный состав и CRC; рядом сохраняется SHA-256.
- В версии 0.1.1 добавлены регрессионные проверки всей цепочки `identify → command → TCP`: запросы `INF1`/`INF2` с паролем и без, отсутствие необязательных полей и отклонение некорректных имён команд. До исправления три новых TCP-теста воспроизводили тот же `ValueError`, что и пользовательский журнал. В проверке настоящего HA определение модели тоже выполняется через TCP-эмулятор без подмены `identify`.
- Для предыдущей версии [GitHub Actions](https://github.com/ipmerlin/ha-pjlink-ir/actions/runs/40352571696) подтвердил четыре задания: offline, homeassistant, HACS и hassfest. Результаты текущей версии доступны в [workflow Checks](https://github.com/ipmerlin/ha-pjlink-ir/actions/workflows/checks.yml).
- В версии 0.1.2 добавлена безопасная выгрузка реестров: число объектов, состояние записи, отключённые объекты, привязка к устройству, платформы и SHA-256 установленных файлов. Прямой тест в настоящем HA подтвердил две сущности, одно устройство и две платформы. Отдельные HA-тесты проверяют пустую запись, отключённые сущности, отсутствие обращений к устройствам и отсутствие пароля, адреса и ИК-кодов в выгрузке.
- Для 0.2.0 прямой тест настоящего HA подтвердил создание 14 объектов пяти платформ у одного устройства и сохранившееся ИК-пробуждение. Новые HA-тесты проверяют реальные состояния лампы/ошибок, охлаждение, прогрев, ожидание, отсутствие ложных показаний без сети, неподдерживаемые и временно отклонённые команды, динамическое появление второй лампы, AV Mute с подтверждением и отсутствие повторов команд.

## Ограничения

- Новое соединение Daylight View требует включённого NETWORK CONTROL и доступного порта Panasonic. Пароль веб-администратора может отличаться от PJLink; его можно задать отдельно. Ошибка соединения не отключает PJLink. Регистрация сущности основана на модели, а доступность — на фактическом ответе. Эта версия не устанавливалась в действующий HA и не отправляла команды физическому проектору.

- После обновления до 0.1.2 пользователь подтвердил появление объектов и работу ИК-пробуждения Panasonic FW300NT. Присланная диагностика HA 2026.10.4 подтвердила две активные сущности, одно устройство и доступную сеть. Исходную причину прежнего отсутствия объектов установить не удалось.

- В Windows pytest-плагин не запускается из-за Linux-модуля `fcntl`; полный pytest-набор успешно выполнен в Linux CI. Прямой тест `tests/ha_contract.py` прошёл и в Windows, и в Linux.
- HACS сообщает необязательное предупреждение об отсутствии `categories`. Стабильный hassfest отклоняет это новое поле, поэтому его пока нет в manifest. Проверки HACS и hassfest проходят; это не запуск без предупреждений. GitHub также сообщает о версии Node.js в используемых внешних actions.
- Исходники опубликованы в [ipmerlin/ha-pjlink-ir](https://github.com/ipmerlin/ha-pjlink-ir). Установка в действующий Home Assistant не выполнялась.
- Новые данные лампы/ошибок и AV Mute ещё не проверены на физическом FW300NT. Работа базового питания и ИК-пробуждения подтверждена пользователем для 0.1.2. Возможность обучения определяется функцией `LEARN_COMMAND`; работа произвольного передатчика зависит от реализации стандартных remote-сервисов его интеграцией.
- Список сохранённых кодов не читается из приватных хранилищ передатчиков. Для готовой команды вводятся её имя/код и, при необходимости, имя устройства.
- Недоступность сети не доказывает выключение проектора: без PJLink состояние питания отображается как неизвестное, действия включения доступны, диагностический датчик связи выключен.

## Команды

```text
python scripts/test_offline.py
python scripts/test_offline.py --voluptuous
python scripts/check.py
python tests/ha_contract.py
python -m pytest tests/ha -q
ruff check custom_components tests scripts
python scripts/package.py
python scripts/verify_release.py
```

Для `tests/ha_contract.py` нужен установленный Home Assistant, для pytest — также `pytest-homeassistant-custom-component`. Изолированная среда находится в исключённой из Git папке `.ha-venv`. Тесты не обращаются к домашней сети.
